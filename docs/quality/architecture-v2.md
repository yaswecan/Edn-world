# Décision d’architecture — 7 octobre 2026

Le moteur reste dans Express/Node 22, avec les agrégats SQLite locaux ou PostgreSQL existants et un worker distinct. Aucun framework agentique, nouvelle base ou changement de comptes. La configuration Vercel du dépôt concerne le serveur HTTP ; elle ne prouve pas un déploiement actif. Les appels longs du compte ChatGPT restent dans le lanceur personnel local ; les laboratoires appartiennent à un service séparé.

La chaîne est maintenant : contexte de séance figé → extraction et sources versionnées → analyse documentaire persistée → contrat de conception → contrôles locaux → revue indépendante du plan → rédaction par compétence → supports et références visuelles → candidat immuable → exécution des contrôles → revue indépendante → correction bornée → revalidation. Une réponse syntaxiquement valide ne franchit pas les contrôles métier automatiquement.

`policy.mjs` possède les trois familles, les règles et le manifeste des capacités. Le type de créneau reste indépendant. `contracts.mjs`, `design.mjs` et `quality.mjs` vérifient les mêmes obligations à leurs étapes respectives. Le diagnostic élève reste distinct de l’analyse des sources et des vérifications du moteur.

`generation_calls` contient chaque tentative AVANT son envoi, avec révision, empreinte des entrées, schéma, profil, provision et transitions. Une transaction locale ne garantit pas une facturation unique chez le fournisseur. Les sorties valides, fragments et résultats tardifs restent différents. Les provisions incertaines ne sont pas libérées par une annulation ou une perte de connexion. Les plafonds d’origine restent partagés par toutes les révisions. La recette peut grouper plusieurs préparations sous un plafond commun, réservé atomiquement avant chaque soumission. La concurrence reste à un travail par connexion par défaut ; elle est bornée à trois lorsque la configuration de recette l’autorise.

Le bail et la révision protègent chaque adoption. `generation_revisions` archive l’état remplacé ; une réponse tardive demeure attachée à son ancienne tentative. Une nouvelle politique conserve l’analyse si ses dépendances correspondent, invalide la conception et ses productions et laisse les versions de séance historiques intactes. Un changement de contexte sous une tentative réussie exige une révision explicite avant tout nouvel appel.

Le bouton « Vérifier l’avancement » consulte le travail existant. « Nouvelle tentative de cette étape » autorise une nouvelle consommation lorsque la récupération est impossible. La route ChatGPT actuelle ne permet pas de promettre la récupération d’un flux interrompu. L’API Responses peut être configurée séparément en background ; sa consultation GET récupère la même réponse sans soumettre une nouvelle inférence.

Le débogueur JavaScript exécute le sous-ensemble existant de l’interpréteur dans un Worker : points d’arrêt, instructions, variables et interruption bornée. Chaque pas rejoue déterministement ce code isolé ; aucune animation prédéfinie ne simule son résultat. Le shell utilise le PTY et les conteneurs Linux existants, sans réseau, accès aux secrets ou socket Docker. Le DOM utilise le laboratoire Chromium prévu par le dépôt ; son debugger universel et SSH ne sont pas déclarés disponibles.

Les références Design sont des captures PNG du corrigé, produites avec JavaScript et réseau désactivés dans un contexte navigateur sans compte. `lesson_assets` conserve les pixels et leur empreinte. Les routes vérifient classe et version publiée avant de les fournir aux élèves ; le code du corrigé reste privé. L’export inclut les mêmes images et fichiers que la version affichée.

Les migrations ajoutent seulement `generation_revisions` et `lesson_assets` au schéma agrégat existant ; les anciens documents restent acceptés. Le retour arrière se fait par `EDEN_QUALITY_PIPELINE=0` et restauration du code précédent, sans supprimer les nouvelles tables ni les versions. Une restauration des données impose l’arrêt des deux processus et une sauvegarde préalable de la base courante, des artefacts et du coffre de connexion. Ne jamais remplacer une base active ni supprimer des tentatives élèves pour revenir au code précédent.
