Mon atelier système

Comprendre le parcours.

Ce qui reste sur ton appareil

Le site conserve ton prénom ou ton code, tes réponses, ton code JavaScript et ta progression dans le stockage local du navigateur. Ce n’est pas un compte : il n’y a pas de connexion ni de synchronisation entre appareils.

« Mon espace » permet d’exporter, d’importer et d’effacer les données. Un ordinateur partagé ne protège pas les réponses par mot de passe. Ne saisis pas d’informations confidentielles.

Le fichier de bilan est remis manuellement au professeur. Les réponses du cours restent dans l’export. Pour le simulateur bonus, un partage explicite peut envoyer les essais au service de classe fourni avec ce projet ; ce n’est pas une connexion automatique aux comptes Eden Hub existants. L’hébergeur reçoit les requêtes nécessaires à l’affichage du site ; aucun outil publicitaire ni pisteur tiers n’a été ajouté au projet.

La police Inter peut être chargée depuis Google Fonts si l’enseignant laisse cette option activée. Aucune réponse ne figure dans cette requête. Sans cette ressource, le cours fonctionne avec une police de secours.

Le simulateur bonus et son suivi

Le bonus apparaît après les six missions, le ticket et le bilan. Il ne modifie pas les horaires et n’ajoute pas de note obligatoire. Ton état et les 500 derniers essais sont conservés localement. Le professeur peut recevoir ces essais si le service est déployé et si tu actives le partage avec le code de classe.

Le partage transmet seulement ton code élève, le nombre d’écrans du cours parcourus, tes manipulations du bonus et ta phrase d’explication. Le suivi est stocké dans Neon PostgreSQL, distinct du stockage du navigateur. Par défaut : 30 jours après le dernier envoi (durée configurable). La purge quotidienne est exécutée si le cron Vercel et CRON_SECRET sont configurés ; une purge a aussi lieu à la consultation du tableau professeur. Au plus 2 000 événements sont conservés par session, dont les 1 000 derniers sont affichés. Le professeur peut supprimer une session. Désactiver le partage local ne supprime pas les données déjà reçues.

Il n’y a pas de reprise automatique sur un autre appareil ni d’identification officielle de l’élève. Ne partage pas le navigateur d’un autre élève. Les connexions ne figurent pas dans le bilan exporté.

Des jeux, pas des réglages du PC

Les cartes, la mémoire et le relais du fichier sont des modèles pédagogiques. La machine du jeu a 8 cases RAM, un cœur CPU et pas de mémoire virtuelle. Les droits des dossiers sont fictifs.

Le Moniteur système est observé en lecture seule. Le relevé de secours est explicitement simulé. Il ne mesure rien sur ton appareil.

Dans le mini-labo, ton JavaScript s’exécute dans un Worker arrêté après une seconde. La zone #score est simulée. Ce n’est ni un vrai DOM complet, ni VS Code. Le site ne lit pas tes fichiers et ne modifie pas les réglages du système.

Les vérifications sont formatives, pas un examen sécurisé. Le code du site et les contrôles sont consultables. Le professeur valide les explications.

Le corpus de départ

Adaptation du corpus fourni EDEN_BIOS_OS_CORPUS_EDEN_HUB_MARDI_13H20_16H15.zip : diagnostic des acquis, six missions, horaires du mardi, ticket, fiche finale et schémas au feutre.

Les consignes sont découpées en écrans « observer → reconstruire → tester → expliquer ». Les longs chemins de fichiers et l’extraction de ZIP disparaissent du parcours élève. L’expérience de fermeture de l’éditeur est représentée à l’écran comme une simulation ; le professeur peut la refaire avec VS Code.

Le code score / socre et sa correction restent le problème de la dernière mission. Le support d’exécution a changé, pas l’objectif.
