## BC06-C1-1 — Manipuler le DOM avec le JavaScript

### LIVE CONSOLE // Le clic doit agir

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** JavaScript (vanilla)

### Situation d’entrée

Le bouton de la console ne change jamais l’état du secteur. Dans le TP DOM, relie l’événement au traitement puis au rendu.

### Cours d’introduction proposé

Le DOM représente le document sous forme de nœuds. querySelector sélectionne le premier élément correspondant ; querySelectorAll fournit une collection à parcourir. textContent modifie du texte sans l’interpréter comme HTML ; classList gère des classes ; appendChild insère un nœud créé.

AddEventListener associe un traitement à un événement comme click, submit ou change. Le cycle à expliquer est événement → lecture des données → traitement → mise à jour de l’interface. Évite les sélections nulles, les écouteurs ajoutés plusieurs fois et l’insertion de texte externe comme HTML. Le laboratoire main(input) n’est pas le DOM : la manipulation attendue se fait dans le fichier navigateur complet du TP.

### Exemple

```text
const bouton = document.querySelector("#activer");
bouton.addEventListener("click", () => { document.querySelector("#etat").textContent = "Actif"; });
```

### Production

Répare le fichier TP : clic de changement d’état, ajout d’une alerte, suppression ciblée et changement de filtre.

Mode : TP réel dans l’outil indiqué, hors sandbox

### Critères proposés

- Manipulations DOM réelles
- click/submit/change
- collection parcourue
- console sans erreur sur le parcours

### Transfert individuel

Une nouvelle alerte est ajoutée après le chargement. Comment éviter de dépendre d’un élément qui n’existait pas au départ ?

### Jeu d’amorce — questions et correction professeur

## BC06-C2-1 — Maîtriser les fondamentaux JavaScript

### CLIENT DATA // Le calcul avant l’écran

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** JavaScript (vanilla)

### Situation d’entrée

Les niveaux d’alerte sont affichés comme du texte et le total mélange nombres et chaînes. Remets les fondamentaux au service de l’interface.

### Cours d’introduction proposé

Les fondamentaux JavaScript doivent être mobilisés ensemble : types primitifs, let/const, fonctions, tableaux, objets et conditions. Les fonctions fléchées et méthodes de tableaux facilitent certaines transformations ; Math fournit des opérations numériques. Comprendre les types reste nécessaire pour interpréter les résultats.

Sépare les données reçues, leur validation et le modèle affichable. Nomme les variables selon leur rôle et évite les effets cachés. Var apparaît dans certains codes anciens ; le référentiel privilégie let/const pour les nouvelles productions. L’ES6 ne signifie pas que toute syntaxe moderne est interchangeable ou comprise automatiquement. Teste le traitement indépendamment du DOM.

### Exemple

```text
const niveaux = input.alertes.map(a => Number(a.niveau));
return niveaux.filter(n => Number.isFinite(n)).map(n => Math.max(0, n));
```

## BC06-C2-2 — Contrôler et valider un formulaire de données

### FORM FEEDBACK // Corriger sans perdre

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** HTML / JS

### Situation d’entrée

L’habitant soumet un formulaire incomplet et perd tout son texte. Répare validation, erreurs et confirmation.

### Cours d’introduction proposé

Un formulaire collecte des données nommées et peut être envoyé selon method et action. Les types HTML et contraintes natives guident la saisie ; JavaScript peut compléter les règles et afficher un retour ciblé. Une validation utile dit quel champ pose problème et comment le corriger, sans effacer les données valides.

Associe les messages aux champs et prévois un résumé si nécessaire. Gère le focus, le clavier et l’état d’envoi. Empêche les doublons pendant le traitement, mais rends une nouvelle tentative possible après erreur. Les contrôles client servent l’expérience ; le serveur doit vérifier à nouveau ses propres règles, car le client peut être modifié.

### Exemple

```text
Vide → erreur associée au champ. Valide → envoi en cours. Échec réseau → texte conservé + réessayer. Succès confirmé → message et référence.
```

### Production

Corrige le TP formulaire puis teste vide, email mal formé, succès et échec simulé sans perte de saisie.

Mode : TP réel dans l’outil indiqué, hors sandbox

### Critères proposés

- Validation réelle
- messages associés
- conservation de saisie
- retour clavier
- contrôle serveur distingué

### Transfert individuel

### Jeu d’amorce — questions et correction professeur

## BC06-C2-3 — Identifier et corriger les erreurs JavaScript

### BUG TRIAGE // Trois erreurs, trois pistes

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** DevTools

### Situation d’entrée

Le compteur plante pour une donnée absente, puis donne un total faux après réparation. Distingue syntaxe, exécution et logique.

### Cours d’introduction proposé

Une erreur de syntaxe empêche l’interprétation du code ; une erreur d’exécution survient pendant un traitement ; une erreur logique produit un résultat incorrect sans forcément lever d’exception. Lis le message et son emplacement, reproduis le cas puis observe les valeurs.

Le débogage suit une hypothèse vérifiable : changer un seul facteur utile, exécuter, comparer attendu et obtenu. Console et points d’arrêt aident à inspecter l’état. Les tests fournis vérifient certains comportements mais pas toutes les situations imaginables. Après correction, relance aussi les cas qui fonctionnaient auparavant pour repérer une régression.

### Exemple

```text
Contrat : compteur(0) retourne 0. Code fautif : return input.n || 10; Le zéro valide est remplacé ; aucune exception ne signale cette erreur logique.
```

### Production

Répare le cas zéro dans le laboratoire puis documente une erreur de chaque catégorie dans le TP DevTools.

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- Reproduction
- catégorie argumentée
- hypothèse
- tests fournis exécutés après correction

### Transfert individuel

Le correctif du cas zéro casse l’entrée absente. Comment définir le comportement sans ambiguïté ?

### Jeu d’amorce — questions et correction professeur

Attendu : Une erreur logique

Après correction, relancer les anciens cas sert à…

Un correctif peut modifier d’autres comportements.

## BC06-C3-1 — Exploiter des données depuis une API tierse

### API DISTRESS // Le réseau ne promet pas le succès

**Typologie et niveau source :** Savoir-faire technique · A2

**Outils source :** Fetch API / Postman

### Situation d’entrée

L’interface affiche « tout va bien » même quand l’API renvoie 500. Répare le flux chargement-erreur-succès et vérifie le format des données.

### Cours d’introduction proposé

Fetch renvoie une promesse. Async/await permet d’exprimer l’attente sans confondre réponse et résultat immédiatement disponible. Une réponse HTTP en erreur ne rejette pas automatiquement la promesse fetch : vérifie response.ok ou le statut avant de lire et valider le corps. JSON sérialise des données ; JSON.parse et JSON.stringify travaillent côté JavaScript, json_decode/json_encode côté PHP.

Une API REST expose des ressources et utilise des méthodes comme GET, POST, PUT et DELETE. « DEL » dans la source désigne ici DELETE, correction pédagogique explicitée. Un jeton de test doit rester fictif ; une clé secrète ne doit pas être embarquée dans le frontend. Teste avec Postman les réponses, erreurs et formats, puis relie le flux frontend-backend-base.

### Exemple

```text
const response = await fetch("/api/alertes");
if (!response.ok) throw new Error("Échec HTTP");
const data = await response.json();
if (!Array.isArray(data)) throw new Error("Format inattendu");
```

### Production

Dans le TP local, appelle l’API préparée, affiche les états et traite 200, 401, 500 et JSON inattendu ; reproduis un appel dans Postman.

Mode : TP réel dans l’outil indiqué, hors sandbox

### Critères proposés

- Requêtes réelles au labo
- statut et JSON vérifiés
- erreurs visibles
- jeton fictif
- cycle complet expliqué

### Transfert individuel

Deux recherches partent rapidement ; la réponse de la première arrive en dernier. Comment empêcher un affichage obsolète ?

### Jeu d’amorce — questions et correction professeur

Attendu : Non, vérifier le statut ou response.ok

Le transport et le statut applicatif doivent être distingués.

Une réponse JSON valide est-elle forcément conforme au contrat ?

Attendu : Non, vérifier aussi sa structure

La syntaxe JSON ne garantit pas les champs et types attendus.

## BC06-C3-2 — Introduction à Node.js (culture technique)

### RUNTIME BOOT // Node n’est pas npm

**Typologie et niveau source :** Savoir-faire technique · A2

**Outils source :** Node.js / npm (découverte)

### Situation d’entrée

Le terminal répond « npm : commande non trouvée ». Identifie ce qui manque avant de conclure que le projet est cassé.

### Cours d’introduction proposé

Node.js exécute JavaScript hors du navigateur. Npm est un gestionnaire de paquets et un lanceur de scripts de projet. Package.json décrit notamment les métadonnées, scripts et dépendances. Node -v et npm -v interrogent deux programmes différents ; leur disponibilité dépend de l’installation et du PATH.

Lis le README et la version requise avant d’installer. Place-toi dans le dossier contenant package.json pour lancer un script npm. Un projet sans dépendance tierce peut ne pas nécessiter npm install ; cela ne supprime pas le besoin du runtime. Le navigateur possède un DOM, Node n’en fournit pas nativement. Les commandes administrateur servent à installer selon la documentation, pas à exécuter arbitrairement le projet avec tous les droits.

### Exemple

```text
node -v
npm -v
node mission.mjs
# Dans le bon dossier : npm run test
```
