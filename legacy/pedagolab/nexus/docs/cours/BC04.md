## BC04-C1-1 — HTML5 - Comprendre la sémantique HTML

### SEMANTIC SHIELD // La porte sans nom

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** HTML5, W3C

### Situation d’entrée

L’interface affiche un titre avec un div et une action avec un span. Visuellement tout semble bon ; structure la page pour qu’elle porte aussi du sens.

### Cours d’introduction proposé

HTML décrit la structure et le sens du contenu. Un titre utilise un niveau h1 à h6 cohérent ; un paragraphe utilise p ; un bouton déclenche une action ; un lien possède une destination. Les attributs précisent les éléments et les data-* stockent des données personnalisées sans créer de sémantique accessible.

Les catégories de contenu HTML ne se confondent pas avec display en CSS. Les expressions block/inline du référentiel sont à distinguer du rendu modifiable par CSS. Les éléments vides comme input n’ont pas de balise fermante. La validation HTML aide à repérer les erreurs de structure, mais ne prouve pas à elle seule l’accessibilité ni la qualité du contenu.

### Exemple

```text
<main><h1>État de NEXUS</h1><p>Le secteur est stable.</p><button type="button">Tester le signal</button></main>
```

### Production

Remplace les éléments sans sens par une structure sémantique, puis vérifie les titres et le nom de l’action.

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- HTML corrigé
- hiérarchie expliquée
- résultat du validateur sur le fichier complet

### Transfert individuel

Le designer veut que le titre soit très petit. Faut-il remplacer h1 par un span ?

### Jeu d’amorce — questions et correction professeur

Un bouton dessiné avec un span donne-t-il automatiquement le comportement clavier ?

Attendu : Non, préférer le bouton natif

La sémantique native apporte des comportements que le style ne crée pas.

Changer display modifie-t-il le sens d’un élément HTML ?

Attendu : Non, cela modifie sa disposition

Structure et présentation sont complémentaires, pas interchangeables.

### Notions du socle (texte source, ligne 80)

> Balises sémantiques, attributs, data-attributs
> Niveaux de texte, balises block/inline/orphelines

## BC04-C1-2 — HTML5 - Organiser le squelette d'une page et son layout

### CITY SKELETON // Reconstruire le portail

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** HTML5, Figma

### Situation d’entrée

Un fragment de page arrive sans langue, sans titre de document et avec trois zones principales concurrentes. Reconstruis un squelette exploitable.

### Cours d’introduction proposé

Un document HTML complet contient un doctype, un élément html avec sa langue, un head pour les métadonnées et un body pour le contenu. Le titre du document aide à identifier la page ; l’encodage précise l’interprétation des caractères. Header, nav, main et footer structurent les grandes responsabilités. Section regroupe un thème ; article représente un contenu autonome.

L’intégration à partir d’une maquette commence par l’inventaire des zones et une hiérarchie de titres. Un layout fluide s’adapte à l’espace disponible plutôt que de figer toutes les largeurs. Le rendu graphique vient ensuite. L’aperçu intégré travaille sur un fragment ; le TP exige aussi un document complet vérifié hors de ce fragment.

### Exemple

```text
<!doctype html>
<html lang="fr"><head><meta charset="utf-8"><title>Station NEXUS</title></head><body><header>Station</header><main><h1>Alertes</h1></main><footer>Assistance</footer></body></html>
```

### Production

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- Document complet
- zones légendées
- titre et langue
- layout cohérent avec le zoning

### Jeu d’amorce — questions et correction professeur

Attendu : Dans title, à l’intérieur de head

Le titre du document et le titre du contenu ont des rôles distincts.

## BC04-C1-3 — HTML5 - Formulaires et contenu interactif

### FORM LOCK // Un formulaire qui répond

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** HTML5

### Situation d’entrée

Le formulaire de signalement comporte un champ sans label et une fausse barre de progression. Remets les contrôles au service de l’habitant.

### Cours d’introduction proposé

Un formulaire associe des champs à des libellés explicites. label et son attribut for relient le texte à un id unique. Input, select avec option, textarea et datalist répondent à des besoins différents ; une suggestion datalist ne remplace pas une règle de validation.

Progress représente l’avancement d’une tâche ; meter représente une mesure dans un intervalle connu. Une boîte de dialogue demande une gestion du focus et de sa fermeture ; le composant natif dialog fournit une base, mais son usage doit être testé. Les types de champs, required, bornes et messages améliorent la saisie sans remplacer les contrôles serveur. method et action précisent l’envoi dans un formulaire réel.

### Exemple

```text
<label for="sector">Secteur</label><input id="sector" name="sector" required><label for="detail">Détail</label><textarea id="detail" name="detail"></textarea><progress value="2" max="3">2/3</progress>
```

### Production

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- distinction progress/meter
- essai dialog et focus dans le TP complet

## BC04-C2-1 — CSS3 - Appliquer un style au composant d'une interface

### CASCADE BREACH // Le style qui résiste

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** CSS3

### Situation d’entrée

Tu changes la couleur de la carte, mais elle reste rouge. Trouve la règle gagnante plutôt que d’empiler des !important.

### Cours d’introduction proposé

Une règle CSS associe un sélecteur à des déclarations propriété:valeur. La feuille peut être liée au document ; les sélecteurs ciblent éléments, classes, attributs ou états. La cascade départage les déclarations selon leur origine, importance, couche, spécificité et ordre lorsque ces critères le permettent.

Les unités répondent à des besoins différents : px, pourcentages, rem ou unités de viewport ne décrivent pas la même référence. Le modèle de boîte sépare contenu, padding, bordure et marge. Avec box-sizing: border-box, la largeur déclarée inclut padding et bordure, pas la marge. Observe les styles calculés et les règles barrées dans DevTools pour expliquer un résultat.

### Exemple

```text
.alert { color: #e9f2ff; background: #10182a; padding: 1rem; border: 1px solid #91a7c3; box-sizing: border-box; }
```

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- sélecteur ciblé
- styles calculés commentés
- largeur/padding/bordure distingués

### Transfert individuel

### Jeu d’amorce — questions et correction professeur

## BC04-C2-2 — CSS3 - Mettre en forme une interface

### GRID DEFENSE // Ranger la station

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** CSS3

### Situation d’entrée

Les cartes débordent du tableau de bord et les boutons ne s’alignent plus. Utilise les bons axes et la bonne grille.

### Cours d’introduction proposé

Flexbox organise principalement un axe à la fois. Flex-direction définit l’axe principal ; justify-content distribue sur cet axe, align-items sur l’axe transversal. Wrap autorise plusieurs lignes. Grid organise lignes et colonnes ensemble ; les pistes, zones et gap structurent un layout.

Ce sont des outils complémentaires : une carte peut contenir une rangée Flexbox dans une page Grid. Évite les hauteurs fixes injustifiées et les alignements obtenus par espaces dans le texte. Teste les contenus longs, les cartes supplémentaires et une largeur réduite. Un layout robuste garde un ordre de lecture logique dans le HTML.

### Exemple

```text
.dashboard { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 1rem; }
.actions { display: flex; align-items: center; gap: .75rem; flex-wrap: wrap; }
```

### Production

Construis la grille du tableau de bord et aligne les actions d’une carte. Ajoute un contenu long pour tester.

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- Grid pour le layout
- Flexbox pour les actions
- axes expliqués
- aucun débordement imposé par un contenu courant

### Transfert individuel

### Jeu d’amorce — questions et correction professeur

Attendu : Vertical

La direction change la lecture de justify-content et align-items.

Pour gérer explicitement lignes et colonnes ensemble ?

Attendu : Grid

La grille décrit des pistes et des relations de layout.

### Notions du socle (texte source, ligne 85)

> Flexbox : alignement, distribution, direction, wrap
> Grid : grilles, colonnes, zones, gap
> Cas d'usage : Flexbox pour composants, Grid pour layouts

## BC04-C2-3 — CSS3 - Appliquer un système de design et respecter la charte graphique

### TOKEN SYNC // Une seule identité

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** CSS3, Figma

### Situation d’entrée

Chaque page a sa propre couleur d’alerte. Centralise la règle sans casser les variantes autorisées par la charte.

### Cours d’introduction proposé

Un système de design rassemble des règles et composants cohérents. Les variables CSS peuvent exprimer des valeurs récurrentes : couleurs, espacements, typographie ou rayons. Une convention de nommage comme BEM est un choix d’organisation ; son intérêt vient de sa cohérence, pas du nom lui-même.

Compare l’intégration à la maquette fournie dans plusieurs états. Factorise les règles communes, garde les variantes explicites et documente les exceptions. Une modification d’un jeton doit avoir un effet prévisible sur les pages concernées. Respecter la charte inclut aussi lisibilité et accessibilité, pas seulement une ressemblance visuelle.

### Exemple

```text
:root { --space-card: 1rem; --surface: #10182a; }
.alert-card { padding: var(--space-card); background: var(--surface); }
.alert-card--critical { border-inline-start: .3rem solid #ffba73; }
```

## BC04-C3-1 — Savoir expliquer le responsive design et le mobile first

### POCKET TERMINAL // Commencer petit

**Typologie et niveau source :** Savoir · Non précisé

**Outils source :** Non précisés

### Situation d’entrée

Le panneau desktop devient inutilisable sur un écran étroit. Défends les fonctions essentielles avant d’ajouter de l’espace.

### Cours d’introduction proposé

Le responsive design adapte l’interface à l’espace et aux capacités d’usage. Mobile first commence par une présentation utilisable dans un espace réduit, puis enrichit le layout lorsque le contenu dispose de plus de place. Il ne consiste pas à cacher arbitrairement les fonctions sur téléphone.

Distingue taille physique, résolution et pixels CSS. Les breakpoints se choisissent d’après les besoins du contenu, pas une liste éternelle de modèles de téléphones. Vérifie lecture, navigation et actions, avec zoom et orientation différente. La largeur n’est pas une mesure de la capacité ou de l’attention d’un utilisateur.

### Exemple

```text
Base : une colonne, boutons lisibles, navigation disponible. À partir de l’espace nécessaire : deux colonnes et informations secondaires mieux réparties.
```

## BC04-C3-2 — Adapter une interface à tous les supports

### RESIZE RUN // Survivre à tous les écrans

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** CSS3

### Situation d’entrée

Une carte de 900 pixels déborde sur le terminal de poche. Répare le CSS, puis cherche la largeur où ton choix cesse de tenir.

### Cours d’introduction proposé

Les media queries appliquent des règles selon des caractéristiques de l’environnement, notamment la largeur. En mobile first, les styles de base restent utilisables avant l’enrichissement par min-width. Flexbox et Grid adaptent la distribution ; minmax, wrap et largeurs relatives évitent certaines rigidités.

Les unités vw et vh dépendent du viewport ; vmin et vmax de ses dimensions minimale ou maximale. Elles ne remplacent pas une réflexion sur le contenu. Les tableaux et cartes riches nécessitent parfois une zone de défilement ou une présentation alternative. Teste entre les breakpoints, avec longs mots, zoom et clavier, puis justifie tes arbitrages.

### Exemple

```text
.panel { width: 100%; max-width: 60rem; }
.cards { display: grid; gap: 1rem; }
@media (min-width: 48rem) { .cards { grid-template-columns: 1fr 1fr; } }
```

Supprime le débordement, ajoute un breakpoint justifié et teste la page complète à 360, 768 et 1280 pixels CSS.

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- traitement du tableau
- justification du breakpoint

## BC04-C4-1 — Comprendre les enjeux du référencement

### SEARCH BEACON // Être trouvé pour la bonne raison

**Typologie et niveau source :** Savoir · Non précisé

**Outils source :** Non précisés

### Situation d’entrée

Le portail est en ligne mais introuvable pour les habitants. Distingue découvrabilité, publicité et promesses de visibilité automatique.

### Cours d’introduction proposé

Le SEO vise à rendre un contenu compréhensible et accessible aux moteurs de recherche afin qu’il puisse apparaître dans des résultats pertinents. Le SEA correspond à la publicité dans les moteurs ; le display à des formats publicitaires sur des espaces de diffusion. Ces canaux ont des logiques et coûts différents.

Crawl, indexation et classement sont distincts : une page accessible au robot n’est pas assurée d’être indexée ni bien classée. Le terme GEO concerne la visibilité dans des réponses génératives ; les pratiques évoluent et aucune recette ne garantit une citation. Le développeur agit surtout sur accès, structure, métadonnées, performances et cohérence du contenu, sans promettre un rang.

### Exemple

```text
Une page utile, accessible par des liens, avec titre descriptif et contenu lisible offre des signaux techniques compréhensibles ; ce n’est pas une garantie de première place.
```

### Production

Classe les leviers par canal, puis propose trois vérifications techniques avant toute dépense publicitaire.

Mode : Production et observation humaine

### Critères proposés

- Distinction SEO/SEA/display/GEO
- crawl-indexation-classement
- promesses non garanties identifiées

## BC04-C4-2 — Appliquer les bonnes pratiques de référencement côté développeur

### CRAWLER RESCUE // Le portail lisible

**Typologie et niveau source :** Savoir-faire technique · Non précisé

**Outils source :** VS Code

### Situation d’entrée

Le titre vaut « Document », les images utiles n’ont aucune alternative et les liens disent tous « ici ». Rends la page compréhensible.

### Cours d’introduction proposé

Le référencement technique commence par une page accessible aux robots et utile aux personnes. Un title descriptif, une hiérarchie cohérente, des liens explicites et des métadonnées pertinentes aident à comprendre le contenu. La meta description peut servir à présenter une page, sans garantir son affichage exact.

Les textes alternatifs décrivent la fonction des images utiles ; une image purement décorative reçoit une alternative vide adaptée. Réduire les ressources inutiles et choisir des images dimensionnées améliore l’usage. Le lazy loading convient aux images hors écran initial, pas systématiquement à l’image principale. Les bonnes pratiques ne garantissent ni indexation ni position.

### Exemple

```text
<title>Signaler une panne — Station NEXUS</title>
<meta name="description" content="Signaler une panne et suivre son traitement.">
<img src="plan.png" alt="Plan des trois secteurs desservis">
```

### Production

Corrige métadonnées, titres et liens sur le fichier complet, puis documente les choix pour les images.

Mode : Atelier navigateur + vérifications manuelles

### Critères proposés

- Document avant/après
- éléments techniques expliqués
